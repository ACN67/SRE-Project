# 软件需求规格说明书

**项目名：** 智能体动态记忆管理系统

**团队：** 收手吧阿组

**成员：** 吴宇轩、郭柏村、杨林涛、刘星宇、**常珂舒**

## 1. 引言

### 1.1 文档目的

本文明确智能体动态记忆管理系统应提供的功能、数据与接口约束，以及验证需求的方法，为团队开发、系统测试和课程验收提供统一依据。

### 1.2 项目背景与目标

长期对话中的工作、计划和个人状态会不断变化。传统相似度检索可能将过时记录与最新记录同时召回，造成回答不符合查询时间；但删除旧记录又会损害历史问答能力。

本项目基于 LoCoMo 多会话对话数据，构建具有原文来源的结构化记忆（Memory），根据问题及时间条件检索、判断状态关系并选择有效证据。系统应提供 Web 浏览与问答功能，并比较 Full Text、Vector RAG、Dynamic 三种方法的表现。

### 1.3 主要术语

| 术语 | 含义 |
|---|---|
| Memory | 从对话中提取、包含内容、时间和来源的结构化事实 |
| 来源引用 | 通过样本、会话和轮次定位原始对话的标识 |
| Vector RAG | 检索相关 Memory 后直接回答，不进行状态关系判断 |
| Dynamic | 在相同候选上判断状态关系、选取有效 Memory 后回答 |

## 2. 系统总体描述

### 2.1 系统定位与流程

系统为可在单机运行的课程研究原型。离线阶段完成 LoCoMo 导入、Memory 构建及检索索引；查询阶段分析用户问题，检索相关记忆，并根据选择的回答方法生成结果。Full Text 直接使用同一样本的原始对话；Vector RAG 使用检索结果；Dynamic 进一步解析更新、替代与冲突关系。三种方法的结果统一提供给 Web 和评测程序。

### 2.2 系统范围

系统应支持原始对话加载和来源回查、结构化 Memory 抽取与 JSON 导出、查询分析与检索、动态状态判断、证据约束问答、Web 可视化，以及三路对照评测。Web 与离线评测应使用一致的核心业务结果，避免产生两套相互矛盾的判断。

### 2.3 数据范围

正式课程实验采用 LoCoMo 中 4 段开发对话和 2 段独立测试对话：

| 数据组 | 原始位置 | 用途 |
|---|---|---|
| main_dev | 第 1—4 段 | 主要开发与参数确定 |
| extra_dev | 第 5—8 段 | 扩展检查 |
| test | 第 9—10 段 | 独立测试，不用于调参 |

所有数据以真实样本 ID 和冻结快照识别。测试答案、证据标注与状态 Gold 仅供独立评分使用，不得进入抽取、检索或回答生成流程。

## 3. 功能需求

### 3.1 对话数据处理

| 需求 | 验收要点 |
|---|---|
| 系统应按冻结配置导入 LoCoMo，保留样本、会话、轮次、发言人和时间信息及其原始顺序。 | 样本身份、划分和轮次顺序与原始数据一致。 |
| 系统应支持以样本、会话和轮次标识回查原文；可用图像描述须明确标注，不冒充发言人原话。 | 来源准确，空文本轮次不丢失。 |
| 文件损坏、身份不符或来源重复时应拒绝加载。 | 返回明确错误，不编造记录。 |

### 3.2 结构化记忆构建

| 需求 | 验收要点 |
|---|---|
| 系统应从对话抽取人物、事件和状态等事实，区分已发生事实、计划、假设和不确定表述。 | 固定样例中的计划不被误判为已实现状态。 |
| 每条 Memory 应保留内容、主体、属性、时间和至少一条可回查的真实来源。 | 记录符合统一数据格式，引用均存在。 |
| 系统应支持 Memory 的 JSON 导出、校验及回读；重复抽取应按明确规则去重。 | 有效产物可重新读取，身份与来源一致。 |
| 构建失败或部分完成时应保留诊断，不得将不完整结果用于正式检索和问答。 | 失败与完整成功状态明确区分。 |

### 3.3 查询分析与记忆检索

| 需求 | 验收要点 |
|---|---|
| 系统应识别当前状态、历史状态、状态历程、事件等问题意图，并独立处理显式或隐含时间条件。 | “曾经”不被视为只查询最新；时间矛盾不被静默忽略。 |
| 系统应在选定样本内检索相关 Memory，按稳定顺序返回候选，并能补充有关的历史状态。 | 候选不跨样本、无重复，顺序可核对。 |
| Vector RAG 和 Dynamic 应共享同一组最终候选及排名。 | 同一问题的候选 ID、顺序和预算相同。 |

### 3.4 动态状态解析

| 需求 | 验收要点 |
|---|---|
| 系统应依据主体、属性与时间证据识别 UPDATE（进展）、SUPERSEDE（替代）和 CONFLICT（冲突）。 | 固定状态变化及矛盾样例的关系可复核。 |
| 系统应对每条候选作出 RETAIN（保留）、EXCLUDE（排除）或 UNRESOLVED（未确定）决定。 | 有效集合恰好包含本次判定为 RETAIN 的记录。 |
| 当前问题应使用最新有据可查的适用状态；历史问题应保留对应旧状态，不删除历史记录。 | 当前与历史查询能使用不同的适用证据。 |
| 无法消解的相关冲突、未知时间或尚未实现的计划不得变成确定事实。 | 保留冲突来源或不确定说明。 |

### 3.5 证据约束问答

| 需求 | 验收要点 |
|---|---|
| 系统应接收样本、问题及可选日期，按所选方法提供统一结构的问答结果。 | 三路输出格式一致，方法可辨认。 |
| 回答涉及人物经历和状态时，应由实际送入生成过程的对话或 Memory 支持。 | 不虚构事实或来源引用。 |
| 应明确区分成功回答、无证据、时间不确定、未解决冲突和执行错误。 | 异常测试中各状态不会相互冒充。 |

### 3.6 网页交互与可视化

| 需求 | 验收要点 |
|---|---|
| 用户应能选择样本、浏览 Memory、查看详情和对应原始轮次，无需先提问。 | 页面可展示列表、详情、来源和空结果。 |
| 用户应能输入问题、选择回答方法，查看答案、相关证据及 Dynamic 状态关系。 | 回答、候选及状态决定可查看。 |
| 页面应区分未构建、部分构建、无证据和服务错误，不能把合成演示数据标作真实结果。 | 不同状态有清楚提示，刷新页面不重复触发抽取。 |

### 3.7 对照实验与评测

| 需求 | 验收要点 |
|---|---|
| 系统应使用相同题集和可比较的模型条件运行 Full Text、Vector RAG、Dynamic。 | 记录逐题方法、输入条件和预测结果。 |
| 应报告问题回答成绩、证据检索 Recall@K 和动态状态判断指标。 | 依冻结评分规则可复算；缺少正式 Gold 则标注无法计算。 |
| 应保存逐题预测、证据、失败信息和运行配置；Gold 只在预测保存后供评分读取。 | 能离线重新评分，失败题不被隐性剔除。 |

## 4. 非功能需求

| 要求 | 验证标准 |
|---|---|
| **正确性与可追溯性** | 来源真实且可回查；状态与答案有证据支持，不伪造事实。 |
| **数据隔离与安全** | Gold 不进入业务输入；密钥及敏感原文不进入代码库或错误日志。 |
| **可靠性** | 区分空结果、部分构建、模型失败及业务不确定性，不将执行错误当作无证据。 |
| **可复现性** | 固定数据划分，记录模型、Prompt、配置、评分规则及代码版本。 |
| **接口一致性** | 跨模块遵守公共 Schema 2.1；Web 与评测程序使用统一业务输出。 |
| **资源约束** | 输入 Token 超限应按明确规则处理并记录；当前抽取窗口初始上限为 4096 Token、重叠 2 条轮次。 |
| **可维护性与可用性** | 接口变更同步测试与文档；Web 能清楚展示数据状态和来源。 |

## 5. 主要数据对象

| 对象 | 必要信息与约束 |
|---|---|
| 对话数据 | 样本 ID、Session、Turn、发言人、原文及可选时间、图像描述；不包含 Gold。 |
| 结构化 Memory | 唯一 ID、样本、内容、主体/属性、事实性质、时间及来源引用；支持 JSON 校验回读。 |
| 查询与候选 | 问题、样本、可选日期、查询意图、时间条件、候选 ID、顺序及来源。 |
| 状态与回答 | 记忆关系、逐项保留决定、有效集合、回答文本、状态及证据引用。 |

## 6. 典型使用场景

### 6.1 浏览记忆并查看来源

| 项目 | 内容 |
|---|---|
| 使用者及条件 | Web 用户；目标样本已加载且 Memory 可用。 |
| 操作流程 | 选择样本 → 浏览并选择 Memory → 查看详情 → 打开原始来源。 |
| 异常与结果 | 空列表、未构建或无效引用应明确提示；有效来源能够回查。 |

### 6.2 查询当前状态

| 项目 | 内容 |
|---|---|
| 使用者及条件 | Web 用户；Memory 与索引可用。 |
| 操作流程 | 询问“现在在哪里工作？” → 检索新旧记录 → 判断更新或替代 → 使用最新适用证据回答。 |
| 异常与结果 | 如果缺少当前状态证据，不将过去状态无限延续为确定事实。 |

### 6.3 查询历史状态

| 项目 | 内容 |
|---|---|
| 使用者及条件 | Web 用户；历史 Memory 可用。 |
| 操作流程 | 询问“2023 年 1 月在哪里工作？” → 解析历史时间 → 选取当时适用的记忆并展示来源。 |
| 异常与结果 | 时间无法可靠判断时说明不确定；新状态不能抹去旧事实。 |

### 6.4 处理冲突或证据不足

| 项目 | 内容 |
|---|---|
| 使用者及条件 | Web 用户；输入含互斥信息或缺乏依据的问题。 |
| 操作流程 | 检索相关证据 → 识别冲突或不足 → 返回相应说明及可用来源。 |
| 异常与结果 | 无证据、时间不确定、未解决冲突及系统错误应明确区分，不随意给出确定答案。 |
