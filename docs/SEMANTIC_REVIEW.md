# DeepSeek 语义事实审核

`scripts/stage_b_semantic_review.py` 对已冻结的私有事实队列逐窗调用 DeepSeek-V4.1-Flash。官方 API 型号名为 `deepseek-flash`；调用启用 thinking/high，不设置 `max_tokens`，单路顺序执行且 SDK 重试数为 0。它不会重新抽取事实，也不会读取 Gold。必须由操作者提供 `DEEPSEEK_API_KEY`，密钥不写入审核产物。

```powershell
$env:PYTHONPATH = (Get-Location).Path + '\src;' + (Get-Location).Path
python -B scripts/stage_b_semantic_review.py `
  --queue <冻结的私有 queue.json> `
  --output-dir <独立的私有审核目录> `
  --max-new-calls 1
```

`--max-new-calls` 限制**本次运行新增的 HTTP 请求数**；默认 0，只回读已有响应。每次请求开始前写入 attempt 记录，成功后另存原始模型响应和 Token 用量。若请求结果不确定或失败，程序停止并拒绝自动重试；操作者须核查该 attempt 的实际计费和远端状态。部分窗口完成时不会生成最终批准文件。全部完成后可用 `--max-new-calls 0` 幂等回读；若最终文件部分写入，程序仅补齐与同一响应严格一致的缺失文件。

历史 v2 响应可以用 `scripts/stage_b_semantic_derive.py --queue <queue.json> --source-approval <v2批准文件> --source-authority <v2权限文件> --output-dir <全新私有目录>` 离线导出 v3 审核文件；不会发起新 API 请求，也不会覆盖 v2 原件。

全部窗口完成后，工具才输出 `semantic_review_approval.json`、`semantic_review_authority.json` 和 `semantic_receipts.json`。新运行的审核身份固定为 `deepseek-v4.1-flash-semantic-v3`，不得改写为人工姓名。验证器重新核对冻结队列指纹、每窗请求指纹、模型身份、完成状态、原始响应、决策顺序，以及每条批准事实引用的原文片段；多来源事实必须引用所有来源并明确确认关系。引用不完整或命中 v3 高风险保护规则时降为 `unclear`。修改、遗失或替换响应文件会导致审核验证失败。旧 v2 响应及审批保留并可按原策略核验，但不能用作新的正式发布。

模型的 `supported` 是**语义判断**，不是数学证明。来源原文确实包含所引片段，也不保证该片段蕴含草稿事实。正式投入无人工逐条审核的生产路径前，须对独立标注样本报告误批率与漏批率，并重点检查说话人、时间、否定、计划和跨来源关系。现有委托审核结果可用于开发集分歧分析，不能兼作独立验收集。语义审核的产物目录应与现有委托审核正式产物分开；分歧未评估前不要覆盖后者。

生产发布入口只接受按 v3 保护规则可重放的模型审核文件；已知存在误批的原始 v2 文件返回 `SEMANTIC_REVIEW_QUALITY_PENDING`。对未来长对话，模型是主要语义判断者，程序负责来源引用、身份、时间/语气和高风险弃权检查；不需要人工逐条默认审批。独立标注集的质量评测仍是扩大部署前的重要验收，不能从单个开发样本推断普遍准确率。
