# 11月1日会议记录

**会议主题：** 全体模块开发进度汇总、下一周整合联调及 Final Presentation / 最终 Milestone 安排

**参与成员：** 全体成员

本次会议首先统计10月末各模块的开发与交付情况，随后讨论11月2日开始的整合、联调、测试以及课程最终展示和 Milestone 材料的安排。会议确认，接下来的重点将由个人模块开发转向**统一集成、功能稳定和最终交付准备**。

## 一、各模块截至11月1日的进度

**根据本次会议各成员的进度汇报：A、B、C、E 四个分支的计划内模块开发已经完成；D 模块以 ZIP 文件形式交付。** 这里的“开发完成”是指各自负责的模块成果已形成，不代表它们已经全部合并进 `main`，也不代表跨模块调用或正式实验已经通过最终验收。

| 模块 | 会上确认的交付状态 | 下一步需要核验的事项 |
|---|---|---|
| **A：公共服务与评测** | A 分支开发完成，包含统一 LLM Runtime、Full Text 基线、三路批量预测与评测、统一只读服务、纯向量补充消融、二维统计及离线自检等。 | 检查最后收尾变更、公共接口与 B/C/D/E 的一致性，贯通真实开发集流程，补齐验收证据。 |
| **B：数据与 Memory** | B 分支开发完成，已交付数据处理、Memory 抽取与构建产物相关代码。 | 核对数据快照、Memory manifest、严格回读、样本 ID 和来源引用，向 C/A 提供可验证产物。 |

## 二、下一周整合与联调的主要安排

计划从11月2日开始集中推进跨模块集成，优先使核心链路跑通并形成可以重复验证的测试与日志。

1. **整理交付与接口清单。** 汇总 A/B/C/E 分支与 D 的 ZIP 交付物，检查各模块源码、依赖、配置、公共 DTO、接口文档和测试。重点确认 `main` 与个人分支的差异，避免遗漏未合并提交。
2. **按上游依赖顺序接线。** 先核验 B 的来源仓库、Memory 构建与产物回读，再接通 C 的索引、查询分析与候选加载；其后对接 D 的状态解析、决策与 Dynamic 回答；最后由 A 的共享服务/Runner 和 E 的 Web 完成调用。
3. **集中解决公共接口问题。** 对照 `TECHNICAL_SPEC.md` v2.2 与 `docs/contracts.md` 核对 Snapshot、MemoryArtifact、CandidateSet、ResolutionResult、AnswerResult、BuildStatus 及 SourceRef。需要改公共契约时，先确认影响模块，再共同修改和测试，不直接在某个分支里另造一套类型。
4. **逐批审查与合并。** 各模块保留原提交历史，优先通过 PR 合并到稳定 `main`；D 的 ZIP 先进行文件审查并确定对应模块的引入方式，不将其默认为已进入 Git。每次合并后运行单元、合同、集成和 Mock smoke 测试，必要时补充回归用例。
5. **开展完整链路联调。** 以受控开发样本检查“原文导入 → Memory 构建 → 检索 → 状态判断 → QA → Web 与评测结果保存”，并覆盖时间冲突、历史状态、无证据、构建失败、索引失效和来源回查。正式 Gold 仅能由预测落盘后的评测路径读取，不能进入业务输入。

上述安排属于下一周的工作计划，不计为11月1日已经完成的测试或合并。若具体模型或 Embedding 设置还未冻结，先记录为待决参数，不为了演示而在多个模块中设置不同默认值。

## 三、Final Presentation 的准备

会议安排启动课程最终展示（Final Presentation，简称 **Final Pre**）的准备工作。展示以已经完成的真实系统为中心，重点说明**为什么设计动态记忆管理、各模块如何协作、三路对照的设计与实际效果、可回查的证据及系统演示**，避免仅罗列源码或 Mock 截图。

初步分工方向：A 汇总整体架构、公共服务、实验方案和指标；B 整理数据来源、Memory 抽取及产物校验；C 说明查询分析、检索和候选；D 提供状态关系、有效 Memory 选择及案例；E 准备网页流程和展示截图。组内再统一文案、图示、演示数据与时间分配，并进行至少一次完整演练。正式实验结果若尚未完成，不应把 synthetic 测试写成正式性能结论。

## 四、最终 Milestone 材料及会议结论

最终 Milestone 的材料整理与联调并行推进：核对课程要求，完善项目报告、主要功能与验收说明、接口与测试记录、Git/PR 提交过程、团队分工、会议截图及演示材料。之前的 Milestone 文档和过程文件继续作为编写依据，不重新编造已完成工作或实验结果。

会议最后确定下一阶段优先级为：**先完成可审查的代码整合和接口联调，再稳定功能、补充必要的真实开发集实验与测试证据，最后完善 Final Pre 和 Milestone 提交材料**。暂未核实的提交截止时刻、演示具体时间和格式，以课程通知和后续组内确认为准。
