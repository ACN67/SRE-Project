# 自动事实审核（保守离线策略）

真实 Memory 的审核现在有两条明确区分的路径：已有的委托/人工审核文件，以及 `auto-extractive-v1` 机器审核。机器路径不冒用人员身份，也不调用模型或网络。它只确认能在**单条引用语句**中找到足够文本锚点、说话人和时间/语气一致的事实；多来源关系、仅有图像说明、无法确定指代和改写跨度大的事实保持 `unclear`，不会发布。自动检查结果不是人工审签，也不等于语义蕴含证明。

## 从队列生成审核材料

在已经完成抽取并导出 `queue.json` 后，运行：

```powershell
$env:PYTHONPATH = (Get-Location).Path + '\src;' + (Get-Location).Path
python -B scripts/stage_b_review_tool.py --queue <private-review/queue.json> --auto-output-dir <独立审核目录> --run-kind real
```

输出 `auto_review_approval.json` 和 `auto_review_authority.json`。目录须在抽取运行状态目录之外；工具使用独占创建，拒绝覆盖旧记录。对于单次运行的 batch，将这两个文件交给 `scripts/stage_b_repair_runner.py` 的 `--review-file` 和 `--authority-file`；对于原 59 窗加补采 4 窗的跨运行队列，使用 `scripts/stage_b_publish_merged.py`。两种入口只允许在**已获批准、已完成且可只读重放的 batch**上发布。复放不得发起新的模型调用。正式发布入口会再次按冻结队列、原始来源和自动策略重算批准项；仅有签名文件或模型自称可信不足以放行。

自动审核与原有人工审核共享同一事实级批准格式，但 `reviewer_id` 固定为 `auto-extractive-v1`，`authority_version` 还绑定当前策略源文件的 SHA256。验证器对机器路径逐项重算规则；即使有人改动批准文件并重新计算文件哈希，也不能把机器策略判为 `unclear` 的事实改成 Approved。Memory 的生产来源记录会保留这个机器审核者 ID。人工审核仍按原有权限文件验证，不受机器路径替代或静默转换。

## 能力边界

- 规则追求低误批率，不追求覆盖全部事实。`main_dev/conv-30` 63 窗、713 条草稿的离线试跑中，机器批准 **148** 条，另 **565** 条保持 `unclear`。这 148 条与本轮委托审核记录对照，没有命中其中 25 条未批准项；这只是单样本开发集对照，不是独立测试集精度。
- 被排除的事实不会进入 Memory，相关问题可能缺少可用证据。系统应呈现证据不足，而不是补造答案。需要更高覆盖率时可走 [DeepSeek v3 语义审核](SEMANTIC_REVIEW.md)：模型作主要判断，程序保留响应并核对引文和高风险语气/状态；它仍须用独立样本评测，不能简单降低词面门槛或把单样本对照当成精度证明。
- 四窗补采后的合并队列属于跨运行来源。`stage_b_publish_merged.py` 提供独立的只读重放与可选正式发布入口；调用方必须提供冻结 Manifest 与 Queue 的预期 SHA256，以及原补采授权、审核与权限文件。发布时另外保存逐窗抽取来源清单，并在加载时核验其字节哈希；原始 59 窗与补采 4 窗的不同 Prompt 指纹保留在该清单中。产物与索引目录必须置于原抽取状态及仓库之外。不要通过重新付费抽取 63 窗来绕过此限制。
- 本路径不读取 Gold、不触发 DeepSeek、不更改原始 checkpoint，也不会自动下载模型。生成审核文件本身不发布 Memory；必须由发布入口严格回读后才能供 C 建索引。
