# v2.2修正内容

**定版原则：** 只补充四处接口执行规则，不改项目技术路线；技术文档为 **v2.2**，现有公共 DTO Schema **仍为 v2.1**。

| 问题 | 确定的解决措施 |
|---|---|
| **IC-001：数据容器及来源仓库交接** | 在公共 `contracts/` 统一定义 `ConversationSession`、`ConversationSample`、`DatasetBundle` 和 `SourceRepository`；使用真实 sample ID 及联合来源键；冻结快照和划分前不允许正式加载，禁止 Gold 进入业务 DTO。 |
| **IC-002：构建部分失败的诊断传递** | 保留严格 `build_memories() -> list[MemoryRecord]`，新增 `build_memories_with_report() -> MemoryBuildResult`；记录每个窗口结果和 `partial_build`。有窗口失败时旧接口必须报错，不得返回貌似完整的列表。 |
| **IC-003：manifest 与索引失效** | manifest 固定 `manifest_format_version=1`，保存数据/配置/Prompt/模型/窗口/Memory 完整性信息及 SHA256；先校验再原子发布。严格加载只接受 complete；partial 仅供开发预览，C 默认拒绝，版本变化重建索引或报 `INDEX_STALE`。 |
| **IC-012：只读服务异常状态** | A 增加 `get_build_status`；区分未构建、部分构建、加载失败、完整但零事实等情况；`get_turn` 不依赖 Memory；RAG/Dynamic 数据错误使用 `answer_result.status="error"`，不转为 `no_evidence`。 |

**执行分工：** A 统一公共合同和服务；B 实现数据、Memory 与 manifest；C 执行加载/索引失效检查；E 统一使用 A 的只读服务。优先落实 IC-001～IC-003，随后对接 IC-012。

**实施说明：** v2.2 技术文档已写成确定规则；相应新类型及函数仍需按该规则补充代码、`docs/contracts.md`、fixtures 和合同测试。本次仅生成桌面文档，不修改仓库或声称新增接口已实现。
