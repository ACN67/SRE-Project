## 一、项目交付要求

### 1.1 项目交付目标

基于LoCoMo长期多会话对话数据，开发一个支持结构化记忆构建、动态状态解析、有效记忆检索和可视化的Web应用。

系统需要完成以下功能：

1. **结构化Memory构建：** 从长期对话中提取人物、事件、时间和状态等信息，保存记忆内容、时间、原始会话及轮次，支持统一JSON导出。
2. **相关Memory检索：** 根据用户问题，从完整历史记忆中自动检索相关信息。
3. **动态状态解析：** 判断记忆之间的RETAIN（保留）、UPDATE（更新）、SUPERSEDE（替代）及CONFLICT（冲突）关系，确定当前问题及时间条件下的有效Memory。
4. **问题回答：** 基于有效Memory生成答案，并保留对应证据。
5. **Web可视化：** 展示结构化Memory、原始对话证据、记忆状态关系、解析过程及问答结果。
6. **实验评测：** 完成QA F1、证据检索Recall@K及动态状态更新判断准确率的评测，并与Full Text和Vector RAG基线进行比较。

**数据要求：** 使用课程指定的6段LoCoMo对话，其中4段为开发集、2段为独立测试集。其余4段可用于扩展评测。

Graph Memory、多跳推理、记忆合并与压缩、自适应检索等属于可选扩展，不作为初期开发重点。

## 二、项目实现原理

系统采用模块化方式开发，整体流程如下：

```text
LoCoMo长期对话数据
        ↓
数据预处理与结构化Memory构建
        ↓
Memory存储与JSON导出
        ↓
用户问题 → 相关Memory检索
        ↓
动态状态关系判断
        ↓
有效Memory选择
        ↓
问题回答与证据输出
        ↓
Web可视化展示
```

各模块的基本职责如下：

| 模块 | 功能 |
|---|---|
| 数据与Memory构建 | 将原始对话转换为结构化记忆 |
| 记忆检索 | 根据问题检索相关历史Memory |
| 动态状态解析与QA | 判断记忆关系、选择有效Memory并生成答案 |
| Web应用 | 提供用户交互和结果可视化 |
| 评测与系统集成 | 实现基线及评测流程，连接各模块并验证整体运行 |

系统的主要特点是能够根据问题和时间条件判断记忆是否仍然有效，而不只是检索语义相似的信息。

具体算法、模型、技术栈及接口形式将在后续讨论中确定。

## 三、团队分工

项目采用五人模块化开发，每位成员负责一个主要技术模块。

组长额外承担项目初始化、开发协调及最终整合工作，同时承担独立的技术开发任务，保证实际技术工作量约占项目的五分之一。

| 成员 | 主要分工 | 工作内容 |
|---|---|---|
| **A（组长）** | 评测、基线与系统集成 | 初始化GitHub仓库、制定基础规范、实现评测框架与Full Text基线、协调模块接口、最终整合 |
| **B** | 数据与Memory构建 | LoCoMo数据处理、结构化Memory抽取及JSON导出 |
| **C** | 记忆检索 | Memory检索算法、检索接口及Vector RAG基线 |
| **D** | 动态状态解析与QA | 记忆状态关系判断、有效Memory选择及问题回答 |
| **E** | Web应用与可视化 | Web界面、交互功能、记忆关系与证据展示 |

### 共同职责

- 独立完成各自模块的开发与测试。
- 遵守统一的GitHub协作规范。
- 及时沟通模块接口和依赖问题。
- 保留个人开发记录及Git提交历史。
- 参与最终系统测试、项目报告及展示准备。

各成员的详细技术任务与验收标准将在后续模块设计阶段确定。

## 四、开发组织与项目管理

### 4.1 开发组织

项目采用统一GitHub私有仓库进行版本管理。

- 组长负责仓库初始化和基础目录建立。
- 各成员通过独立开发分支开展工作。
- 模块接口和数据格式由小组统一确定。
- 代码通过Pull Request或经协商的方式合并。
- 项目文档和过程材料统一存放于仓库。
- 各模块优先实现基本功能，再考虑优化与扩展。

具体技术栈、目录结构、分支命名及代码规范后续统一讨论。

### 4.2 小组会议制度

**会议平台：腾讯会议**

**固定会议时间：**

- 每周三晚上22:00
- 每周日晚上22:00

**单次会议时长：不超过30分钟。**

会议主要讨论：

1. 各成员当前进度与已完成工作。
2. 开发中遇到的问题及需要协调的事项。
3. 模块接口、依赖及集成问题。

每位成员自行规划具体开发时间，但应保证按阶段交付，发现影响整体进度的问题时及时沟通。

## 六、项目执行原则

1. **模块独立、统一协作：** 五位成员各自负责主要开发模块，组长负责协调和集成。
2. **工作量合理分配：** 组长承担额外管理职责，但仍需负责约五分之一的技术开发工作。
3. **优先完成必做功能：** 确保系统完整运行，再考虑性能优化与扩展功能。
4. **开发过程可追溯：** 保留代码提交、会议记录、测试及任务完成情况。
5. **按阶段推进：** 前三周完成开发，第四周原则上不增加复杂功能。
6. **共同完成交付：** 项目报告、测试与最终展示由全组共同参与。

本指导文档作为项目初期统一工作安排，具体技术实现、成员任务和开发规范将在后续讨论中逐步补充与完善。
